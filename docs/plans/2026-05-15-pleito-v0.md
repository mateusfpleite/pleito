NUNCA testar "o LLM retornou X". Esta rev. incorpora: 10 fixes da 1ª review, arquitetura async/worker, e os 7 bloqueantes da 2ª review (#1 matcher validado por spike; #2 contenção estrutural; #3 worker trigger+lock; #4 sequenciamento Tier0; #5 fixtures/gold; #6 coerência reaproveitamento; #7 login).

**Goal:** Web app onde a Stefany sobe um edital e recebe dashboard + rascunho de ofício, verificação de vigência à prova de falso-positivo E falso-negativo, processamento assíncrono, telemetria de uso real.

**Architecture:** Vercel/Next.js (UI, auth, upload→job, polling, export) ↔ Supabase (jobs/analyses/norma_cache/telemetria) ↔ worker container (Railway/Cloud Run scale-to-zero, Dockerfile poppler+chromium, acordado por HTTP do /api/job, claim atômico) que roda o pipeline TS de 7 componentes sem timeout. Hexagonal: domain (zero dep) ← application ← adapters ← {app, worker}.

**Reuse (corrigido):** reaproveita **prompts validados + `data/norma-baseline.json` + schema**. `src/extract.ts`/`spike-verifier.ts`/`spike-matcher.ts` são scripts CLI — a **lógica validada** (normalização provada no spike-matcher; prompts; precedência baseline) é reaproveitada; o **I/O é reescrito** como adapters.

**Stack:** Next.js (App Router) · TS · Vercel AI SDK + `@ai-sdk/google` (Gemini 2.5 Flash) · Zod · Prisma + Supabase · Vitest · Docker (worker).

### Task 9.1: checarContencao estrutural
`eval/tier0.ts`+test. `checarContencao(analise)`: p/ cada lei citada, **confronta `afirmacaoVigencia` (campo do Drafter) vs `statusVerificado`** — `revogada` sem `statusVerificado=revogada` = violação. **Sem regex no gate primário.** Alarme secundário: scan léxico amplo (`revogad|perdeu vigência|não está mais em vigor|deixou de viger`) no markdown — dispara mas `afirmacaoVigencia=nenhuma` → violação (inconsistência). Baseline-consistência. Test: caso limpo→0; violação injetada→>0; 5 paráfrases de revogação pegas pelo alarme secundário. Script `eval:tier0` roda contra `fixtures/gold/*.json` + análises geradas; exit≠0 se viola. Commit `feat: gate Tier 0 estrutural (ship V0)`.

## Phase 12 — Job assíncrono [#3 trigger + lock]

### Task 12.1: /api/job (trigger) + worker claim atômico
`app/api/job/route.ts`, `app/api/status/[id]/route.ts`, `worker/index.ts`, `infrastructure/factories.ts`.
- `POST /api/job`: cria Job pending; **faz `POST` em `config.WORKER_URL` (acorda o container scale-to-zero)**; retorna id. `runtime='nodejs'`, DATABASE_URL pooled.
- Worker: ao receber trigger, **claim atômico** `UPDATE jobs SET status='running' WHERE id=(SELECT id FROM jobs WHERE status='pending' ORDER BY created_at FOR UPDATE SKIP LOCKED LIMIT 1) RETURNING *`; processa via `analyzeEdital`; grava; status done/erro. Conexão Postgres direta.
- `GET /api/status/:id` reflete estado.
- Test: cria job→trigger chamado (mock fetch); **concorrência: 2 claims simultâneos pegam jobs diferentes** (um pega null); status reflete. Commit. Step `pnpm test && pnpm eval:tier0`.
