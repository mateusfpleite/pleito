# Pleito V0 Implementation Plan (rev. pós plan-review)

> **For Claude:** REQUIRED SUB-SKILL: superpowers:executing-plans. Aplicar @superpowers:test-driven-development e @superpowers:testing-anti-patterns. NUNCA testar "o LLM retornou X" — testar lógica determinística (normalização, matcher, gates, parsing, invariantes de contenção). Esta revisão incorpora os 10 required changes da plan-review + arquitetura async/worker + observabilidade.

**Goal:** Web app onde a Stefany sobe um edital e recebe dashboard estruturado + rascunho de ofício, com verificação de vigência à prova de falso-positivo, processamento assíncrono e telemetria de uso real.

**Architecture:** **Split:** Vercel/Next.js (UI, auth, upload→job, polling, export) ↔ Supabase (jobs/analyses/norma_cache/telemetria) ↔ **worker container** (Railway/Cloud Run, Dockerfile c/ poppler+chromium, scale-to-zero) que roda o pipeline TS de 7 componentes sem timeout. Hexagonal: domain (zero dep) ← application (workflow + 2 gates) ← adapters ← {app, worker}.

**Tech Stack:** Next.js (App Router) · TypeScript · Vercel AI SDK + `@ai-sdk/google` (Gemini 2.5 Flash) · Zod · Prisma + Supabase Postgres · Vitest · Docker (worker).

**Reference:** `src/extract.ts`, `src/spike-verifier.ts` são **scripts CLI** — serão **reescritos como adapters** (não "portados"): a lógica de prompt/baseline está validada, a estrutura I/O não. `data/norma-baseline.json` pronto. `fixtures/{jaborandi,niteroi,dombasilio}.txt` + `fixtures/baserate/*.txt` reais.
